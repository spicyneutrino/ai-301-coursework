# Rubric: is this a good first issue?

## Checks

| Check                                     | Evidence                                                                                                                                 | Pass condition                                                                                                                                                                                                                                                                                                                                          | Weight    |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| Maintainer activity                       | Repo-facts block and the most recent merged pull requests. Check the merge dates of the latest 5 merged PRs.                             | Pass if at least one pull request was merged within the last 30 days.                                                                                                                                                                                                                                                                                   | required  |
| Recent repository use                     | Repo-facts block, GitHub Releases page, and recent default-branch commit history.                                                        | Pass if the repository has had a release within the last 6 months **or** at least one commit merged to the default branch within the last 30 days.                                                                                                                                                                                                      | required  |
| Stale contribution backlog                | Open pull requests and issue-linked pull requests. Check PR creation/update dates and whether they remain unmerged.                      | Pass if there are no more than 3 open pull requests that have had no activity for more than 30 days.                                                                                                                                                                                                                                                    | preferred |
| Issue is unclaimed                        | Issue body, labels, assignees, linked pull requests, and comment thread.                                                                 | Pass if the issue has no assignee, no open linked PR implementing it, and no commenter who clearly states they are currently working on it.                                                                                                                                                                                                             | required  |
| Contribution is allowed by project policy | `CONTRIBUTING.md`, README, issue and pull-request templates, repository documentation, labels, and maintainer comments.                  | Pass if there is no explicit repository policy or maintainer instruction preventing this type of contribution. Reject if the repository states that the contribution type is not accepted, requires prior approval that has not been obtained, is reserved for maintainers, or otherwise conflicts with an explicit contribution rule.                  | required  |
| Issue scope is bounded                    | Issue body, acceptance criteria, referenced files/components, and maintainer comments.                                                   | Pass if the issue describes one coherent bug, feature, or change that could reasonably be addressed in one focused pull request. Reject if it explicitly requires a repository-wide rewrite, major architecture redesign, broad migration, or multiple independent features.                                                                            | required  |
| Expected outcome is identifiable          | Issue body, maintainer comments, reproduction details, screenshots, and linked context.                                                  | Pass if the intended result can be identified from the available evidence, such as expected behavior, desired change, reproduction case, acceptance criteria, or a clear contrast between current and desired behavior. Formal acceptance criteria are not required if completion can still be objectively determined.                                  | required  |
| Investigation path exists                 | Issue body, linked files, stack traces, screenshots, reproduction steps, labels, maintainer comments, and relevant repository structure. | Pass if the evidence provides a concrete way to begin investigating the issue, such as reproducible behavior, an error message, affected feature/component, relevant file/module, screenshot, linked discussion, or another identifiable entry point. Do not require the exact implementation location to already be known.                             | required  |
| No unresolved external blocker            | Issue body and comment thread.                                                                                                           | Pass if the issue does not depend on an unresolved upstream bug, unavailable private service, pending design decision, or another unmerged change that must be completed first.                                                                                                                                                                         | required  |
| Recent maintainer response                | Comment thread on the issue and recent related issues.                                                                                   | Pass if a maintainer has commented on the issue or a closely related issue within the last 30 days.                                                                                                                                                                                                                                                     | preferred |
| Newcomer-sized change                     | Issue body, referenced code locations, maintainer comments, and related changes.                                                         | Pass if the issue appears to represent one coherent contribution that could be completed in one focused pull request. Reject when the available evidence clearly indicates a large migration, repository-wide refactor, major redesign, or several independent features. Lack of an exact file count or implementation estimate alone is not a failure. | required  |

## Verdict rule

Accept the issue only if every **required** check passes.

A required check graded `unclear` counts as a failure because there is not enough evidence to safely select the issue as a first contribution.

Preferred checks do not change an `accept` verdict to `reject`. They are used only to rank accepted issues: issues passing more preferred checks should rank above otherwise similar accepted issues.
